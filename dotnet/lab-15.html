Đọc lý thuyết liên quan →

Mã mẫu minh họa từng bài, có thể cần ghép với lớp, Form hoặc CSDL ở lab trước. Không dán tất cả ví dụ cùng tên lớp vào một tệp. Chuỗi desktop dùng .NET Framework 4.8; chuẩn bị runtime Crystal Reports tương thích cho Lab 13–16.

1. Mục tiêu cần đạt được

  • Thiết kế chiến lược xử lý lỗi theo tầng.
  • Kiểm tra an toàn dữ liệu và tạo ngoại lệ nghiệp vụ.
  • Ghi log có cấu trúc vào tệp.
  • Đọc cấu hình từ App.config và bảo vệ thông tin nhạy cảm ở mức phù hợp.
  • Đóng gói và kiểm thử ứng dụng trên máy đích.

2. Công cụ và dữ liệu chuẩn bị

  • Visual Studio 2022.
  • Ứng dụng quản lý sinh viên từ Lab 12-14.
  • App.config, thư mục Logs và công cụ Publish/Setup phù hợp.

3. Liên kết trong chuỗi bài lab

Ngữ cảnh xuyên suốt: Gia cố chất lượng phần mềm trước khi tích hợp cuối khóa. Lab 16 yêu cầu ứng dụng có logging, cấu hình, xử lý lỗi và gói cài đặt sử dụng được.

4. Chuẩn bị trước khi thực hành

  • Tạo bản sao ổn định của ứng dụng trước khi chỉnh sửa.
  • Tạo thư mục Logs và kiểm thử quyền ghi.
  • Chuẩn bị một máy ảo/máy khác để thử cài đặt.

5. Bài tập có hướng dẫn và code mẫu

1. Ngoại lệ nghiệp vụ tùy biến

Yêu cầu: Tạo BusinessException và sử dụng khi dữ liệu vi phạm quy tắc nghiệp vụ. Gợi ý triển khai: Không dùng exception để thay mọi câu lệnh điều kiện; chỉ ném khi không thể tiếp tục luồng.

[Serializable]
public class BusinessException : Exception
{
  public BusinessException() { }
  public BusinessException(string message) : base(message) { }
  public BusinessException(string message, Exception inner) : base(message, inner) { }
}

if (dto.DiemTB < 0 || dto.DiemTB > 10)
   throw new BusinessException("Điểm trung bình phải thuộc [0,10].");

2. Dịch vụ kiểm tra dữ liệu dùng chung

Yêu cầu: Tạo ValidationResult và phương thức kiểm tra SinhVienDTO trả nhiều lỗi cùng lúc. Gợi ý triển khai: BUS dùng kết quả này trước khi gọi DAL.

public class ValidationResult
{
  public bool IsValid { get { return Errors.Count == 0; } }
  public List<string> Errors { get; } = new List<string>();
}

public static ValidationResult Validate(SinhVienDTO dto)
{
  ValidationResult result = new ValidationResult();
  if (string.IsNullOrWhiteSpace(dto.MaSV)) result.Errors.Add("Thiếu mã sinh viên.");
  if (string.IsNullOrWhiteSpace(dto.HoTen)) result.Errors.Add("Thiếu họ tên.");
  if (dto.DiemTB < 0 || dto.DiemTB > 10) result.Errors.Add("Điểm không hợp lệ.");
  return result;
}

3. Ghi log vào tệp

Yêu cầu: Tạo Logger ghi thời gian, mức độ, thông điệp và chi tiết exception vào thư mục Logs. Gợi ý triển khai: Tự tạo thư mục, không làm ứng dụng lỗi thêm khi ghi log thất bại.

public static class Logger
{
  private static readonly object Sync = new object();

    public static void Error(string message, Exception ex)
    {
      try
      {
        string dir = Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "Logs");
        Directory.CreateDirectory(dir);
        string file = Path.Combine(dir, DateTime.Now.ToString("yyyyMMdd") + ".log");
        string line = string.Format("{0:O} | ERROR | {1}\r\n{2}\r\n",
           DateTime.Now, message, ex);
        lock (Sync) File.AppendAllText(file, line, Encoding.UTF8);
      }
      catch { /* Không để lỗi log làm dừng ứng dụng */ }
    }
}

4. Xử lý lỗi tập trung ở giao diện

Yêu cầu: Phân biệt BusinessException, SqlException và lỗi không xác định; log chi tiết nhưng chỉ hiện thông báo phù hợp. Gợi ý triển khai: Không hiển thị connection string hoặc stack trace cho người dùng.

try
{
  _bus.Add(dto);
}
catch (BusinessException ex)
{
  MessageBox.Show(ex.Message, "Dữ liệu chưa hợp lệ");
}
catch (SqlException ex)
{
  Logger.Error("Lỗi CSDL khi thêm sinh viên", ex);
  MessageBox.Show("Không thể cập nhật dữ liệu. Vui lòng thử lại.");
}

  catch (Exception ex)
  {
    Logger.Error("Lỗi không xác định", ex);
    MessageBox.Show("Ứng dụng gặp lỗi. Mã lỗi đã được ghi nhận.");
  }

5. Đọc cấu hình từ App.config

Yêu cầu: Đưa connection string và thư mục xuất báo cáo vào cấu hình. Gợi ý triển khai: Tham chiếu System.Configuration cho .NET Framework.

<configuration>
 <connectionStrings>
  <add name="QLSinhVien"
     connectionString="Data Source=.;Initial Catalog=QLSinhVien;Integrated Security=True"
     providerName="System.Data.SqlClient" />
 </connectionStrings>
 <appSettings>
  <add key="ReportFolder" value="Reports" />
 </appSettings>
</configuration>

string cs = ConfigurationManager.ConnectionStrings["QLSinhVien"].ConnectionString;
string folder = ConfigurationManager.AppSettings["ReportFolder"];

6. Bài tập tự thực hiện - không có code gợi ý

6. Global exception handler

Yêu cầu: Đăng ký Application.ThreadException và AppDomain.UnhandledException; ghi log và đóng an toàn.

7. Log xoay vòng

Yêu cầu: Giới hạn kích thước hoặc số ngày lưu log; tự động lưu trữ/xóa tệp cũ.

8. Mã hóa connection string

Yêu cầu: Tìm hiểu và áp dụng ProtectedConfiguration cho phần connectionStrings trên máy triển khai.

9. Kiểm tra trước khi chạy

Yêu cầu: Tạo màn hình kiểm tra SQL Server, database, thư mục ghi log, Crystal runtime và quyền ghi tệp.

10. Đóng gói ứng dụng

Yêu cầu: Publish hoặc tạo bộ cài; triển khai trên máy sạch, ghi lại các phụ thuộc và lỗi phát sinh.

7. Sản phẩm nộp

  • Mã nguồn có xử lý lỗi và logging theo tầng.
  • Tệp cấu hình mẫu không chứa mật khẩu thật.
  • Bộ cài hoặc thư mục Publish chạy trên máy đích.
  • Biên bản kiểm thử triển khai: môi trường, bước cài, kết quả, lỗi và cách khắc phục.
